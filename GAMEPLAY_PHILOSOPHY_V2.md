# INSIDE GREY ROOM — NOUVELLE PHILOSOPHIE GAMEPLAY
## Spécification de référence — scénarios 001–020

> Ce document décrit la philosophie de gameplay à intégrer sans réécrire inutilement le cœur existant du jeu.
> La vérité canonique de chaque scénario doit rester intacte sauf nécessité explicite.
> L’objectif est d’augmenter l’immersion, la tension sociale, la clarté des rôles et la variété des scènes sans transformer Inside Grey Room en jeu sur téléphone.

---

# 1. PRINCIPES NON NÉGOCIABLES

## 1.1. L’application est une autorité procédurale, pas le centre de la partie

L’application :
- gère les phases ;
- gère les chronos ;
- gère les convocations ;
- gère les informations privées ;
- gère les trames ;
- gère les actions de rôle ;
- gère les décisions irréversibles ;
- conserve la vérité canonique ;
- orchestre les événements ;
- verrouille les choix ;
- produit la révélation finale.

Les joueurs :
- parlent ;
- mentent ;
- interrogent ;
- négocient ;
- se confrontent ;
- enquêtent ;
- observent ;
- doutent ;
- protègent leurs intérêts ;
- prennent les décisions humaines.

Règle directrice :

> L’application est autoritaire sur les phases qu’elle ouvre, silencieuse sur les interactions qu’elle n’a pas ouvertes.

Aucun système de transcription, d’écoute sémantique ou d’analyse automatique des conversations humaines.

---

## 1.2. Immersion avant durée

La durée totale d’une partie n’est pas une contrainte prioritaire.

Une partie peut être longue si elle reste vivante.

Ce qu’il faut éviter :
- la répétition ;
- l’attente passive ;
- les écrans trop longs ;
- les tâches administratives ;
- les séquences identiques ;
- les informations sans conséquence ;
- les pouvoirs gadgets.

Règle :

> On ne raccourcit pas une scène utile uniquement pour réduire la durée.
> On supprime la monotonie, pas la profondeur.

---

## 1.3. Langage

Le langage doit être :
- froid ;
- simple ;
- violent par les faits ;
- concis ;
- immédiatement compréhensible ;
- adulte ;
- institutionnel ;
- jamais romanesque ;
- jamais sur-explicatif.

Mauvais :
> Une horrible découverte bouleverse l’enquête.

Bon :
> AUTOPSIE  
> La victime était encore consciente après la première blessure.  
> Elle a vécu 17 minutes.

Mauvais :
> Une révélation terrifiante remet tout en question.

Bon :
> ACCÈS 03:12  
> La porte a été ouverte de l’intérieur.

La violence doit venir du fait brut, pas des adjectifs.

---

# 2. STRUCTURE DES TROIS CYCLES

## 2.1. Scénarios avec Analyste

### Pré-enquête — **3 minutes communes et parallèles**

La partie a déjà commencé.

Pendant les mêmes **3 minutes**, chaque groupe vit une préparation différente.

#### Enquêteur + Analyste
- préparation ;
- lecture commune des éléments disponibles ;
- première stratégie ;
- réflexion sur la première convocation ;
- aucune convocation ne peut encore être lancée.

#### Suspects — Salle d’attente
Les Suspects sont déjà réunis physiquement.

Ils doivent pouvoir parler librement.

Selon le scénario :
- ils font connaissance s’ils ne se connaissent pas ;
- ils reprennent naturellement contact s’ils se connaissent déjà ;
- ils discutent des faits qu’ils connaissent ;
- ils observent les réactions ;
- ils testent les versions des autres ;
- ils peuvent mentir, minimiser, protéger quelqu’un, accuser ou éviter un sujet ;
- ils peuvent déjà commencer à construire des alliances ou de la méfiance.

L’application ne leur donne **aucun mini-jeu** et aucune série de questions.

Écran recommandé :

> **SALLE D’ATTENTE**  
> L’enquête n’a pas encore commencé.  
> Vous pouvez parler librement.

Le scénario doit également indiquer clairement ce que chaque personnage sait déjà de ses relations avec les autres.

Exemples :

> **VOUS VOUS CONNAISSEZ DEPUIS 6 ANS.**

> **VOUS NE VOUS ÊTES JAMAIS RENCONTRÉS AVANT CE SOIR.**

> **VOUS CONNAISSEZ KARIM. VOUS N’AVEZ JAMAIS RENCONTRÉ YASSIN.**

> **PERSONNE NE SAIT QUE VOUS AVEZ VU KARIM LA VEILLE.**

Les relations publiques peuvent être connues de tous.

Les relations secrètes restent privées.

#### Avocat
S’il est présent dès le début du scénario :
- il peut rejoindre son client ou ses clients en Salle d’attente si le scénario l’autorise ;
- il peut commencer à écouter et préparer sa défense ;
- il ne reçoit pas de tâche artificielle.

#### Juge / Procureur / Expert / Inspecteur / Journaliste
Ils reçoivent leur briefing propre et prennent leur place prévue par le scénario.

Ils ne doivent pas être artificiellement occupés par l’application.

Le scénario peut autoriser certains d’entre eux à observer ou à circuler dès la pré-enquête, mais uniquement si cela sert réellement le dossier.

#### Fin de la pré-enquête
À **00:00** :
- la pré-enquête se ferme ;
- la première convocation devient disponible ;
- l’Enquêteur choisit qui entre ;
- l’Enquêteur ou l’Analyste peut aller chercher physiquement le Suspect ;
- le Cycle 1 commence avec le premier interrogatoire.

### Cycle 1 — ÉTABLIR LES VERSIONS
- **3 interrogatoires de 8 minutes**
- aucune Assemblée ;
- les rôles spécialisés commencent à travailler en parallèle ;
- tous les chronos sont rigides.

### Transition 1
- Enquêteur + Analyste : **2 minutes**
- puis questions au MJ adaptatif.

### Cycle 2 — METTRE LES VERSIONS SOUS PRESSION
- **2 interrogatoires de 8 minutes**
- **2 événements annexes**
- une Assemblée maximum peut faire partie de ces événements ;
- Confrontations, expertise, témoin, retour Inspecteur, décision judiciaire, négociation, enquête journalistique, etc.

### Transition 2
- Enquêteur + Analyste : **2 minutes**
- puis questions au MJ adaptatif.

### Cycle 3 — RÉSOUDRE
- **3 événements annexes**
- un interrogatoire de 8 minutes peut être l’un des trois événements si l’Enquêteur le souhaite ou si le scénario le rend pertinent ;
- aucun interrogatoire n’est obligatoire ;
- la combinaison dépend du scénario.

Exemples :
- Assemblée + Expertise + Confrontation ;
- Témoin + décision du Juge + Interrogatoire ;
- Retour Inspecteur + Enquête journalistique + Confrontation ;
- Expertise + Assemblée + décision du Juge.

### Pré-verrouillage
- Enquêteur + Analyste : **3 minutes**
- Procureur inclus seulement si le scénario le prévoit ;
- puis conclusions / défenses / verrouillage / révélation.

---

## 2.2. Scénarios sans Analyste

La pré-enquête reste une vraie phase de **3 minutes**.

Pendant ce temps :
- l’Enquêteur prépare seul sa première convocation ;
- les Suspects discutent librement en Salle d’attente ;
- les relations initiales du scénario restent actives exactement comme dans les scénarios avec Analyste ;
- la première convocation ne devient disponible qu’à 00:00.

La structure reste ensuite identique, avec une exception :

### Cycle 3
- **3 créneaux**
- jusqu’à **2 interrogatoires de 8 minutes** possibles.

Exemples :
- Interrogatoire + Confrontation + Interrogatoire ;
- Expertise + Interrogatoire + Interrogatoire ;
- Confrontation + trame + Interrogatoire ;
- trois événements sans interrogatoire si l’Enquêteur n’en a pas besoin.

Justification :
- l’Enquêteur n’a pas le soutien analytique permanent ;
- il peut compenser par davantage de confrontation directe avec les joueurs.

---

## 2.3. État applicatif obligatoire : PRÉ-ENQUÊTE

La pré-enquête doit devenir un **véritable état du moteur de partie**, et non un simple texte de briefing.

État recommandé :

`briefing_roles -> pre_investigation -> cycle_1`

Durée :
- **180 secondes autoritaires**.

Pendant `pre_investigation`, l’application affiche des vues différentes selon le rôle.

### Vue Enquêteur
> **PRÉ-ENQUÊTE — 03:00**  
> Préparez votre première convocation.

- consultation des éléments autorisés ;
- aucune action d’interrogatoire disponible ;
- sélection éventuelle d’un nom possible, mais pas de convocation avant 00:00.

### Vue Analyste
> **PRÉ-ENQUÊTE — 03:00**  
> Préparez l’enquête avec l’Enquêteur.  
> Vous gérez le rythme.

- même chrono serveur ;
- préparation des observations ;
- aucune interaction inutile.

### Vue Suspect
> **SALLE D’ATTENTE — 03:00**  
> Vous pouvez parler librement.

En dessous, uniquement les informations sociales réellement utiles :
- personnes connues ;
- personnes inconnues ;
- relation publique pertinente ;
- relation secrète privée si le scénario en contient une.

Ne pas afficher :
- « posez trois questions » ;
- « faites connaissance avec X » ;
- questionnaire ;
- mission sociale automatique ;
- compteur de conversations.

### Vue des autres rôles
Leur écran doit simplement les installer dans leur fonction :
- Avocat : client(s) / position de défense connue ;
- Juge : cabinet ;
- Procureur : bureau ;
- Expert : briefing technique ;
- Inspecteur : briefing terrain ;
- Journaliste : briefing / relations publiques connues.

### Synchronisation
Tout le monde voit le même temps restant.

À 00:00 :
- transition serveur unique ;
- déverrouillage de `CONVOQUER` ;
- aucun reset des informations privées ;
- aucune téléportation logique ;
- les joueurs se déplacent physiquement.

La pré-enquête ne doit jamais être skippée automatiquement parce qu’un joueur a fini de lire.

---

# 3. CHRONOS

Tous les chronos formels sont rigides.

- 8 minutes = 8 minutes.
- 3 minutes = 3 minutes.
- 2 minutes = 2 minutes.
- fin à 00:00 ;
- aucune prolongation automatique ;
- aucune tolérance parce qu’un joueur « allait finir ».

L’urgence fait partie du gameplay.

L’Enquêteur doit optimiser ses questions.

Le Suspect doit décider quoi cacher, quoi admettre et quoi retourner contre les autres.

---

# 4. CONVOCATION ET DÉPLACEMENT PHYSIQUE

Le principe central actuel est conservé :

> L’Enquêteur décide qui entre.

L’Enquêteur sélectionne la personne à convoquer.

L’application affiche clairement :

> CONVOQUÉ  
> Rendez-vous dans la Grey Room.

L’Enquêteur ou l’Analyste peut aller chercher physiquement la personne.

Le Suspect peut également venir de lui-même selon la mise en scène.

Aucune mécanique de téléportation ou de validation excessive.

La circulation physique fait partie de l’immersion.

---

# 5. GREY ROOM ET ESPACES DE JEU

## 5.1. Grey Room

Lieu des :
- interrogatoires ;
- Confrontations ;
- Assemblées ;
- auditions de Témoins ;
- certaines expertises ;
- décisions importantes.

L’Enquêteur dirige la scène.

---

## 5.2. Salle d’attente

La Salle d’attente existe **dès la pré-enquête**.

Ce n’est pas un écran d’attente.

C’est un espace social permanent.

Lieu des :
- Suspects ;
- Avocat selon scénario ;
- discussions libres ;
- stratégies ;
- négociations informelles ;
- observation du Journaliste ;
- passages éventuels de l’Inspecteur.

Avant même le premier interrogatoire, les Suspects peuvent :
- faire connaissance ;
- reprendre une relation déjà existante ;
- comparer ce qu’ils savent ;
- cacher ce qu’ils savent ;
- tester une version ;
- observer qui semble nerveux ;
- créer une alliance ;
- préparer un mensonge ;
- se protéger ;
- se trahir.

Après le début de l’enquête, cette dynamique continue entre les convocations.

L’application ne doit pas combler les silences.

Elle ne doit jamais transformer la Salle d’attente en mini-jeu.

Les joueurs peuvent :
- parler ;
- mentir ;
- s’accuser ;
- s’aligner ;
- se protéger ;
- se trahir.

La Salle d’attente est donc un **lieu de gameplay humain**, pas une phase inactive.

---

## 5.3. Cabinet du Juge

Le Juge dispose d’un espace isolé.

Il peut :
- recevoir des requêtes ;
- examiner des informations protégées ;
- décider de la portée d’une information ;
- accepter ou refuser certaines demandes ;
- suivre éventuellement un flux vidéo autorisé.

Le Juge doit apparaître propre et institutionnel, même s’il est corrompu dans une variante.

---

## 5.4. Bureau du Procureur

Le Procureur dispose d’un espace isolé.

Il peut :
- préparer son dossier ;
- analyser les responsabilités ;
- négocier avec l’Avocat ;
- saisir le Juge ;
- préparer ses entretiens ciblés ;
- suivre éventuellement un flux vidéo autorisé.

---

## 5.5. Expert

L’Expert peut assister à la Grey Room selon le scénario.

Statut :

> OBSERVATEUR TECHNIQUE

Il :
- s’assoit dans un coin ;
- écoute ;
- observe ;
- n’intervient jamais spontanément ;
- ne pose aucune question ;
- ne corrige pas l’Enquêteur ;
- ne répond pas au Suspect.

Il ne parle que lorsqu’il est :
- formellement convoqué ;
- appelé pour une expertise ;
- admis à une Assemblée ;
- sollicité par une mécanique prévue.

Selon certains scénarios, l’Expert peut être interdit d’observation avant d’avoir rendu sa première analyse.

---

# 6. ASSEMBLÉES

## Cycle 1
Aucune Assemblée.

## Cycle 2
- une Assemblée maximum ;
- tous les rôles concernés y sont admis ;
- pas d’exclusion volontaire ;
- fonction : première coordination réelle de la cellule.

## Cycle 3
- une Assemblée maximum ;
- l’Enquêteur peut exclure certains rôles ;
- Analyste obligatoire s’il existe ;
- l’exclusion devient un choix stratégique.

Exemple :
> ASSEMBLÉE FINALE  
> Analyste requis.  
> Sélectionnez les rôles admis.

Une exclusion peut être pertinente si :
- le Procureur paraît compromis ;
- le Juge semble protéger quelqu’un ;
- le Journaliste représente un risque de fuite ;
- l’Expert n’est pas nécessaire ;
- une discussion doit rester restreinte.

L’application ne confirme jamais qu’un rôle exclu est réellement corrompu.

---

# 7. CONFRONTATIONS

Une Confrontation est une forme spéciale de convocation.

Principe :
- l’Enquêteur décide ;
- l’Analyste peut gérer le déclenchement et le temps ;
- deux joueurs pertinents sont réunis ;
- la scène reste courte et intense ;
- elle doit être prévue ou rendue possible par le scénario.

Le système ne doit jamais écouter les conversations pour décider d’une Confrontation.

Les déclencheurs peuvent dépendre de faits connus du serveur :
- un Suspect déjà entendu ;
- une trame révélée ;
- une expertise ;
- un témoin ;
- une Breaking News ;
- une décision judiciaire ;
- un événement canonique.

---

# 8. ANALYSTE

L’Analyste devient le régisseur opérationnel de l’enquête.

Il :
- gère le temps ;
- surveille les transitions ;
- observe les interrogatoires ;
- note les contradictions ;
- utilise le canal d’enquête si prévu ;
- aide à la reconstruction ;
- répond aux questions du MJ ;
- peut gérer certaines actions d’interface pour laisser l’Enquêteur concentré sur la personne en face de lui.

L’Enquêteur conserve :
- le choix des personnes convoquées ;
- la direction de l’interrogatoire ;
- les décisions stratégiques majeures ;
- la reconstruction finale.

---

# 9. INSPECTEUR

L’Inspecteur possède deux dimensions :

## Terrain
- une action de terrain selon les règles du scénario ;
- résultats canoniques ;
- jamais de mini-jeu artificiel.

## Salle d’attente
L’Inspecteur peut parler à des Suspects.

Ces échanges sont :
- informels ;
- courts ;
- risqués ;
- non équivalents à un interrogatoire complet.

Le Journaliste peut observer ce comportement.

Si l’Inspecteur dépasse la procédure ou mène un contact suspect, le Journaliste peut :
- enquêter ;
- le confronter ;
- publier ;
- collaborer avec lui ;
- utiliser ce contact dans ses objectifs.

Conséquence potentielle :
> CONTACT HORS PROCÉDURE

La conséquence doit être procédurale / narrative / liée à la crédibilité, pas un simple malus abstrait.

---

# 10. JOURNALISTE

Le Journaliste est le rôle le plus mobile.

Il peut :
- observer ;
- parler aux joueurs ;
- envoyer des messages privés ;
- utiliser Breaking News ;
- enquêter sur des joueurs ;
- collaborer avec l’Inspecteur ;
- enquêter sur le fonctionnement même de l’enquête.

## 10.1. ENQUÊTER SUR UNE PERSONNE

Action formelle à partir du cycle 2 selon le scénario.

Le Journaliste choisit :
- une personne ;
- un angle.

Angles possibles :
- Relations ;
- Intérêts ;
- Incohérences ;
- Passé ;
- Contacts ;
- Conflit d’intérêts.

Le système renvoie :
- une information canonique ;
- incomplète ;
- exploitable ;
- jamais une révélation directe de culpabilité ;
- jamais l’objectif privé du joueur.

Exemple :
> ENQUÊTE — KARIM  
> Karim connaissait Yassin avant les événements.  
> Il affirme le contraire depuis le début.

---

## 10.2. Inspecteur ↔ Journaliste

Ils peuvent :
- collaborer ;
- se surveiller ;
- se compromettre ;
- se fournir des pistes.

Option rare :
> ENQUÊTE CROISÉE

Elle combine :
- information de terrain ;
- information humaine / journalistique.

La collaboration ne garantit pas la confiance.

---

# 11. TRIANGLE JUDICIAIRE

## Avocat ↔ Procureur : NÉGOCIATION

Ils peuvent négocier :
- coopération ;
- réduction de responsabilité ;
- information contre contrepartie ;
- reconnaissance partielle ;
- retrait d’une qualification ;
- accord prévu par le scénario.

L’application verrouille uniquement le résultat accepté.

---

## Avocat ↔ Juge : REQUÊTE

L’Avocat peut demander :
- limitation d’une preuve ;
- confidentialité ;
- audition d’un témoin ;
- contestation de la portée d’un élément ;
- protection procédurale.

Le Juge :
- ACCORDE ;
- REFUSE.

---

## Procureur ↔ Juge : SAISINE

Le Procureur peut demander :
- exploitation d’une information protégée ;
- audition ;
- validation d’un accord ;
- décision procédurale ;
- qualification prévue par le scénario.

Le Juge arbitre.

---

# 12. RÔLES CORROMPUS

Certains scénarios peuvent comporter :
- un Juge corrompu ;
- un Procureur corrompu ;
- éventuellement d’autres institutions compromises si le scénario le justifie.

Principe fondamental :

> Le rôle public reste parfaitement propre en apparence.

L’interface ne doit jamais afficher :
- CORROMPU ;
- TRAÎTRE ;
- SABOTEUR ;
- pouvoir de corruption explicite.

Le joueur reçoit un objectif privé.

Exemple :

> OBJECTIF PRINCIPAL  
> Rendre une décision juridiquement défendable.

> OBJECTIF SECONDAIRE  
> Karim ne doit pas tomber.

La corruption passe par :
- les priorités ;
- les décisions ;
- les refus ;
- les accords ;
- les exclusions ;
- la circulation de l’information ;
- l’interprétation des faits.

Elle ne permet jamais :
- d’inventer une preuve ;
- de modifier la vérité canonique ;
- de falsifier un élément système.

---

# 12.1. RELATIONS INITIALES ET IDENTITÉ SOCIALE

Chaque scénario doit définir une **matrice de relations initiales** entre les personnages.

Cette matrice sert directement à la pré-enquête.

Pour chaque paire pertinente, préciser :
- se connaissent / ne se connaissent pas ;
- depuis combien de temps si utile ;
- nature publique de la relation ;
- conflit connu ;
- dette / proximité / hiérarchie / famille / travail si pertinent ;
- relation secrète éventuelle ;
- ce que A sait de B ;
- ce que B sait de A.

La relation peut être asymétrique.

Exemple :
- Karim connaît Yassin ;
- Yassin croit ne jamais avoir rencontré Karim ;
- Karim l’a déjà observé dans un contexte que Yassin ignore.

L’application ne doit révéler à chaque joueur que ce qu’il est censé savoir.

Cette matrice ne doit pas devenir une encyclopédie.

Le texte reste court.

Exemple :

> **KARIM**  
> Vous avez travaillé ensemble pendant deux ans.  
> Vous ne vous êtes pas parlé depuis mars.

ou :

> **YASSIN**  
> Vous ne le connaissez pas.

ou :

> **INFORMATION PRIVÉE**  
> Vous l’avez vu sortir du bâtiment la veille.  
> Il ne sait pas que vous étiez là.

Objectif :
- donner immédiatement de la matière à la conversation ;
- permettre aux joueurs d’entrer dans leur personnage sans scénario récité ;
- faire commencer le mensonge et la méfiance avant la première convocation.

---

# 13. OBJECTIFS

Chaque joueur possède :

> OBJECTIF PRINCIPAL

et

> OBJECTIF SECONDAIRE

Le scénario peut contenir une grande bibliothèque d’objectifs compatibles, mais seulement deux sont montrés au joueur.

Les objectifs doivent pouvoir commencer à influencer le comportement **dès la pré-enquête**.

Exemple :
- un Suspect qui doit protéger Karim peut naturellement se rapprocher de lui dès la Salle d’attente ;
- un Suspect qui doit cacher leur relation peut au contraire faire semblant de ne pas le connaître ;
- un Journaliste qui doit comprendre un conflit d’intérêts peut commencer par observer qui parle avec qui ;
- un Avocat peut déjà sentir qu’un client lui cache quelque chose.

L’application ne demande pas au joueur d’exécuter ces comportements.

Elle lui donne seulement les faits et l’objectif.

---

## 13.1. Suspects

Règle absolue :

> Le Suspect doit sauver ses fesses avant tout.

Son objectif principal doit porter sur :
- éviter d’être reconnu responsable principal ;
- limiter sa responsabilité ;
- sortir de l’enquête ;
- empêcher une accusation excessive ;
- préserver une version crédible.

Exemples :

> OBJECTIF PRINCIPAL  
> Évite d’être reconnu comme responsable principal.

> OBJECTIF SECONDAIRE  
> Fais porter à Karim la décision finale.

ou :

> OBJECTIF PRINCIPAL  
> Fais reconnaître uniquement ta responsabilité réelle.

> OBJECTIF SECONDAIRE  
> Empêche que ton lien avec Yassin soit établi.

Le Suspect peut :
- mentir ;
- minimiser ;
- détourner ;
- accuser ;
- négocier ;
- admettre partiellement ;
- protéger quelqu’un si cela sert ses intérêts.

Il ne peut jamais inventer une preuve.

---

## 13.2. Rôles d’enquête

Leur objectif principal doit rester institutionnel.

Leur objectif secondaire peut créer :
- conflit ;
- protection ;
- suspicion ;
- intérêt caché ;
- collaboration ;
- corruption ;
- rivalité.

Exemple Juge corrompu :

> OBJECTIF PRINCIPAL  
> Rendre une décision défendable.

> OBJECTIF SECONDAIRE  
> Karim ne doit pas tomber.

Exemple Journaliste :

> OBJECTIF PRINCIPAL  
> Publier une information exacte et utile.

> OBJECTIF SECONDAIRE  
> Déterminer pourquoi le Juge protège Karim.

Exemple Inspecteur :

> OBJECTIF PRINCIPAL  
> Établir les faits matériels.

> OBJECTIF SECONDAIRE  
> Obtenir du Journaliste une information qu’il n’a pas encore publiée.

---

# 14. NŒUDS DE TENSION

Les objectifs doivent être écrits à partir de nœuds communs.

Exemple :

## Nœud : Karim doit-il tomber ?

- Enquêteur : déterminer sa responsabilité réelle ;
- Suspect Karim : éviter d’être considéré responsable principal ;
- Avocat : limiter sa responsabilité ;
- Procureur : obtenir une qualification correcte ;
- Juge corrompu : empêcher sa mise en cause ;
- Journaliste : découvrir pourquoi il est protégé ;
- Inspecteur : vérifier matériellement le lien ;
- Expert : préciser ce que la preuve permet réellement d’affirmer.

Une seule question centrale alimente plusieurs rôles.

Objectif :
> les intérêts doivent se recouper.

Éviter les objectifs isolés du type :
- parler trois fois à X ;
- cliquer deux fois sur Y ;
- utiliser le pouvoir avant le cycle 3.

# 15. TRAMES

Il doit exister beaucoup de trames par scénario.

Elles restent toujours canoniques.

Le système :
- peut guider ;
- peut brouiller ;
- peut recontextualiser ;
- peut choquer ;
- ne ment jamais.

Une bonne trame ne donne pas une réponse.

> Elle donne un problème.

---

## 15.1. Types internes de trames

### STRUCTURANTE
Aide à relier les faits.

> BADGE 22:08  
> Seuls Karim et Shayan pouvaient accéder à l’étage.

### AMBIGUË
Vraie, mais dangereuse à surinterpréter.

> MESSAGE 21:51  
> Yassin écrit : « On règle ça ce soir. »

### RECONTEXTUALISANTE
Change la lecture d’une information précédente.

> CONTEXTE  
> Le message concernait une dette ancienne.  
> Aucun lien avec la victime n’est établi.

### CHOC
Fait froid qui change brutalement l’atmosphère.

> AUTOPSIE  
> La victime n’est pas morte à l’endroit où elle a été retrouvée.

---

## 15.2. Les trames peuvent fonctionner en séquence

Exemple :

> CAMÉRA 21:38  
> Karim entre seul dans le bâtiment.

Puis :

> SORTIE  
> Aucun enregistrement de Karim avant 22:16.

Puis :

> SYSTÈME VIDÉO  
> La caméra de la sortie Est était hors ligne.

Les trois informations sont vraies.

La lecture change.

---

# 16. MJ ADAPTATIF

Le MJ ne modifie jamais :
- la vérité ;
- le coupable ;
- les faits ;
- la chronologie canonique.

Il adapte :
- la pression ;
- l’ambiguïté ;
- la clarté ;
- l’ordre de certaines trames compatibles ;
- certains événements annexes compatibles.

---

## 16.1. Questions après cycle

Enquêteur et Analyste répondent séparément :

> VOUS VOUS RAPPROCHEZ D’UNE CONCLUSION ?  
> Non / Un peu / Oui

> LE DOSSIER RESTE DIFFICILE À RELIER ?  
> Non / Un peu / Oui

Les réponses servent à déterminer si le MJ doit :
- clarifier ;
- brouiller ;
- rester équilibré.

Le MJ ne demande jamais :
> Qui soupçonnez-vous ?

Les rôles corrompus ne répondent pas directement à ces questions.

# 19. CONSTRUCTION OBLIGATOIRE D’UN SCÉNARIO

Pour chaque scénario, travailler dans cet ordre :

1. vérité canonique ;
2. chronologie ;
3. responsabilités réelles ;
4. personnages impliqués ;
5. **matrice de relations initiales** ;
6. informations publiques connues avant la première convocation ;
7. informations privées propres à chaque personnage ;
8. **configuration de la pré-enquête et de la Salle d’attente** ;
9. nœuds de tension ;
10. rôles disponibles ;
11. objectifs principaux ;
12. objectifs secondaires ;
13. corruption éventuelle ;
14. bibliothèque de trames ;
15. événements compatibles du cycle 2 ;
16. événements compatibles du cycle 3 ;
17. possibilités de Confrontation ;
18. possibilités d’Assemblée ;
19. actions Journaliste / Inspecteur / Expert / Juge / Procureur / Avocat ;
20. conditions de victoire ;
21. score de force de victoire ;
22. révélation finale.

Ne jamais commencer par ajouter une mécanique.

# 20. RÈGLE DE CONTRÔLE QUALITÉ

Pour chaque ajout, poser cette question :

> Est-ce que cela crée une interaction entre les joueurs, ou seulement une nouvelle interaction avec l’application ?

Si l’ajout ne fait que multiplier :
- les boutons ;
- les écrans ;
- les jauges ;
- les mini-tâches ;

il doit probablement être supprimé.

Inside Grey Room doit provoquer des situations entre les joueurs.

---

## 20.1. CONTRÔLE QUALITÉ DE LA PRÉ-ENQUÊTE

Pour chaque scénario, vérifier obligatoirement :

- les Suspects ont-ils quelque chose de naturel à se dire pendant les 3 premières minutes ?
- savent-ils clairement s’ils se connaissent déjà ?
- les relations publiques sont-elles comprises sans lecture longue ?
- les relations secrètes sont-elles réellement privées ?
- les objectifs peuvent-ils déjà influencer le comportement sans instruction artificielle ?
- la Salle d’attente reste-t-elle libre ?
- l’application évite-t-elle de dicter la conversation ?
- les rôles spécialisés savent-ils où aller pendant ces 3 minutes ?
- la première convocation reste-t-elle verrouillée jusqu’à 00:00 ?
- la transition vers le Cycle 1 se fait-elle sans écran administratif inutile ?

Si les Suspects peuvent passer les 3 minutes sans aucun sujet naturel de discussion, le scénario doit être retravaillé.

---

# 20.2. CONSÉQUENCES DIRECTES POUR LE MÉCANISME DE L’APPLICATION

Le moteur doit considérer que :

1. **la partie commence à la pré-enquête**, pas au premier interrogatoire ;
2. tous les joueurs entrent dans un état commun `pre_investigation` de 180 secondes ;
3. les vues sont personnalisées par rôle ;
4. les Suspects disposent de leur carte relationnelle minimale dès cet état ;
5. les objectifs principal et secondaire sont déjà actifs psychologiquement ;
6. aucune action ne force une conversation ;
7. `CONVOQUER` est verrouillé avant 00:00 ;
8. à 00:00, l’Enquêteur choisit la première personne ;
9. les relations et discussions de Salle d’attente continuent pendant toute la partie entre les scènes formelles ;
10. aucun retour en Salle d’attente ne nécessite un bouton administratif si la phase serveur peut le déterminer automatiquement.

---

# 21. RÈGLE FINALE

> Cycle 1 construit le dossier.  
> Cycle 2 le déstabilise.  
> Cycle 3 le résout.

> Le Suspect cherche d’abord à sauver sa peau.

> Les institutions restent propres en apparence.

> Les objectifs se croisent.

> Les trames sont vraies, mais pas toujours rassurantes.

> Le MJ adapte la pression, jamais la vérité.

> Les chronos sont rigides.

> La durée peut être longue.

> La fatigue ne doit jamais venir de la répétition.

> La partie commence avant le premier interrogatoire.

> La Salle d’attente est un espace de jeu, jamais un écran d’attente.

> Grey Room ne doit pas occuper les joueurs.  
> Grey Room doit provoquer des situations entre eux.
